# mk2cpp 约定

2026-09-13 更新：区分 M1–M4 参考执行层和 M4.5 原生算法层。完整目标见
[13 原生算法重建](13_m45_native_reconstruction.md)；旧指令集成约束不作为原生终态约束。

## 1. 命名

- 翻译块：`blk_<rom>_<flat>`，例如 `blk_r1_0000F86`、`blk_r2_00041220`。
- 已知语义的例程：参考层 `src/hand/` 中用业务名（`voice_alloc`、`pcm_flush` 等），
  `src/gen/` 对应块标注 `// alias: voice_alloc (see hand/)`。
- 变量/字段：引用 `../tools/docs/voice_memory_map.md` 的字段偏移命名，
  如 `V->pitch` 对应 `P(v)+0x2`；未确认的字段保留 `f_0xNN` 并标 TODO。
- 原生算法层按实际职责命名函数、参数和状态字段；原地址映射作为证据和适配信息，
  不要求字段沿用 SRAM 布局。未确认含义应登记，不以猜测命名作为完成依据。

## 1.5 集成 ABI（库形态）

- 项目名 `mk2cpp` = MK2 ROM→C++；**命名禁用 `h8cpp`**（GT 可跑多种固件，本工程
  翻译的是 MK2 的 ROM 代码，不是 CPU 核）。集成开关/变量/表统一 `mk2cpp` 前缀：
  `-mk2cpp`、`mk2cpp_enabled`、`mk2cpp_tab_cp0/1`；公共 API 用 `MK2CPP_`；
  生成函数用 `mk2c_r1_XXXX`。
- 公共符号统一 `MK2CPP_` 前缀（`MK2CPP_Init/CanStep/Step/Version`），放在
  `include/mk2cpp.h`；**不得**定义与 GT 冲突的全局。
- **M1–M4 参考/迁移层**直接使用 GT 的全局 `mcu`、`MCU_Read/Write`、`MCU_SetStatus*`、
  栈/控制寄存器函数；不建第二套内存/寄存器模型。
- **旧指令集成方案**以取指调用处开关接入，不改变参考后端调度顺序。
- **M4.5 原生层**允许拥有合成器逻辑状态、业务接口和逻辑事件/音频调度器，按新后端
  接入；不得把另一套 MCU 寄存器/PC 机器包装成原生状态。正常运行脱离逐指令路径。
  库集成与不新增独立 exe 的要求继续有效。
- **后端选择与复用**：沿用 `-mk2cpp` 进入原生控制分支；不加 flag 保持原模拟器。
  PCM 芯片仿真、LCD、RtMidi、SDL 和资源设施继续复用，必要修改限制在接入边界。
  PCM 内部寄存器/时钟/位精度算法属于保留范围，无需符合固件业务层的去指令化形式。
  共享代码适配与 M5 扩容必须通过不加 flag 的回归，不能改变默认路径行为。
- **原生资产边界**：离线导入原素材为自有 bank；原生启动至保存恢复均不读取原 ROM。
  运行时只解释 bank schema，不用改名/嵌入固件或自动导入回退代替解耦。bank 与其他
  ROM 派生素材保持本地产物；未修改原厂资产等价、无原 ROM 运行和 PCM bit 一致均须验收。
- **透明资产**：标准 WAV + 公开定义是可编辑接口，导出/替换为必交付，修改后重新加载
  必须使用新素材。优先证明 metadata + 解码 PCM 表示完整，任何恢复字段都有明确意义，
  不把原编码副本藏进元数据。素材共用原 PCM 后续处理，
  禁止悄悄使用过期数据或声称改过采样仍应与原厂 bit 一致。具体边界见 16。
- 生成物通过 CMake 变量 `MK2CPP_GEN_DIR` 可选编译；默认不带生成物。

## 2. 生成物 vs 人工

- `src/gen/`：**完全由 `tools/h8lift` 生成**，禁止手改；文件头带
  `// GENERATED by h8lift <version> from ROM sha256 <hash> -- DO NOT EDIT`。
- `src/hand/`：M4 手工逐指令参考实现；通过 dispatch 覆盖 `gen` 的块，保留检查点价值。
- `src/native/`（拟新增）：M4.5 完整算法与状态。迁移时逐模块对照，不回退 M4 成果。
- 每次翻译以 ROM sha256 + 工具版本标记，保证可复现。

## 2.5 原生代码验收

- M4.5 每个切片先建立 [15 §2](15_m45_construction_guide.md#2-每个切片先写一张算法契约)
  的算法契约，依 [14](14_m45_native_architecture.md) 隔离核心、GT 适配与参考验证。
  不能从 asm 自动批量生成业务名包装函数后再补语义说明。
- 函数对应完整业务操作，主体可读出原算法的计算、分支、循环和状态转换；小 helper
  可以保留，但不能由很多一行指令函数构成业务算法的替身。
- 不以零 hex、零 case 或函数改名作为验收；业务层不通过 `mcu.r[]`、PC 分派或原
  SRAM 地址组织运行。格式解码、查表、位掩码和证据对应中的十六进制常量合理保留。
- 按算法需要使用定宽整数、定点或浮点。准确保留影响结果的截断、溢出、符号扩展、
  舍入和饱和，不机械扩大所有类型，不擅自替换 MK2 原算法。
- 每个切片列清状态所有权、全部读写者和时序边界；新增原生状态纳入启动、复位与
  保存恢复。旧 hand 无私有状态的结论不能直接套用。

## 3. 证据与测试

- 任何"GT 行为 X"的断言必须给出来源（`../src/` 行号或 `tools/baselines/` 证据）。
- 每个里程碑的 oracle 脚本放 `tests/`（入库），语料与输出放本地。
- co-sim 分歧必须能一键复现：保存 `out/cosim/divergence_<cycle>.txt` 与触发命令。
- M4.5 原厂对照固定素材来源、输入时序和 PCM/滤波配置，比较逻辑状态、事件、PCM 提交和音频。
  原生后端不要求 H8 寄存器/PC/原 SRAM 字节完全相同；算法可读与运行依赖审计必须
  同时通过。参考 GT 等价与 MK2 实机还原分开记录。

## 4. 目录卫生与 git

- 只提交代码与文档；`src/gen/`、`out/`、`build/`、ROM、trace、快照、日志全部本地。
- `mk2cpp/` 已是公开目录，其派生路径的忽略规则写在公开 `.gitignore` 的
  `mk2cpp:` 段（`mk2cpp/build/` 由通用 `build/` 规则命中），随仓库共享。
  **不得在任何公开文件（md、`.gitignore` 注释等）中写出本地私有路径名或
  本地目录布局**；本地资料的忽略方式不入库文档。提交前用 `git status`
  确认无派生文件、`git check-ignore` 确认命中 `.gitignore`。
- 调试产物写 `out/` 或 `%TEMP%\opencode\`，收尾清空。
- `../build/` 只放运行资产（可执行文件必须与 ROM 同目录，GT 以 exe 目录为 BasePath）。

## 5. 工作流

1. 研究先行：说不清 → 先写 `docs/` 证据文档（含 PC/字节/GT 行号）。
2. 小步翻译：一次一个子系统/一组块，立刻 co-sim。
   M4.5 的单位改为完整算法操作：契约 → 实现 → 独立预期与参考对照；阶段进度按 15，
   不以已替换 PC 或 asm 行数计。
3. 通过 oracle 再提交：提交信息用中文，说明覆盖范围与验证结果。
4. 阻塞登记：写入 `polyphony_256_todo.md`（或 `mk2cpp/docs/99_blockers.md`），
   不留在脑中。

## 6. 与既有工程的关系

- `../tools/` 的反汇编/verify/VM 是 T2 工具，可继续复用；GT `../src/` 是 T0 oracle。
- `../tools/docs/` 是证据主线；`mk2cpp/docs/` 只放本工程特有设计与状态。
- 复音扩展（256 目标）复用 `task_irq_map.md` §4 的 O1–O10 中仍适用的行为判据；
  原硬件窗口/指令时序专属判据需按原生架构重写，并满足 00/13 的真 256 要求。
