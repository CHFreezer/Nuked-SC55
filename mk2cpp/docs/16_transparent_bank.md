# 透明 bank：可试听、可编辑、可替换的采样资产

状态：**设计要求，尚未实现**。2026-09-13，依据用户补充的 WAV 编辑/替换目标。
配套：[13 总目标](13_m45_native_reconstruction.md)、[14 架构](14_m45_native_architecture.md)、
[15 施工规程](15_m45_construction_guide.md)。本文明确扩展 14 §7 的资产要求。

**优先资产模型：公开 metadata + 无损解码 PCM。** 元数据与波形分别保存，共同构成
完整采样表示。先验证组合表示的可逆性，再确定运行接入；不预设终态必须另存原编码
副本或采用两套采样源。可逆性证明方法见 §7.4。

## 1. 用户能做什么

用户打开 bank，应能找到钢琴等音色引用的采样 WAV，直接用普通播放器试听、用音频
编辑器修改，或换成自己的 WAV。文本定义明确说明采样如何分区、调音和循环。
修改后重新加载 bank，合成器必须使用修改后的素材。WAV 导出与替换是正式能力，
不再是仅供研究的可选项；把 ROM 重新打包为无法编辑的 blob 不算完成。

透明资产不要求整台合成器的声音等于直接播放 WAV。WAV 表达采样素材，实际音符还会
经过音高变化、包络、滤波、力度/控制器与效果。试听导出的素材不应先烘焙这些效果。
多个音色可以共用采样，一个音色也可以引用多个采样；目录要让这些关系可追踪。

## 2. 文件组织与来源

第一版以普通目录为权威资产形态，打包/压缩只能是可无损展开的部署方式。示意如下，
文件名不代表当前已恢复了某个具体钢琴样本：

```text
bank/
  bank.json                    格式版本、资产身份、采样及音色索引
  samples/piano_mid.wav        标准 WAV，可独立试听和编辑
  samples/piano_high.wav
  instruments/piano.json       分区、采样引用、调音、循环与参数
  tables/                      原生算法所需的其余具名数据表
  metadata/                    公开的采样元数据，与波形分开
    piano_mid.json             循环/初始化、精度映射及经取证确有必要的恢复字段
```

文本元数据采用有版本的 JSON schema；大型数值表可以二进制存放，但必须公布类型、
布局和索引意义，并提供可读导出。恢复字段同样必须说明，不能把完整原编码副本
藏进 metadata 后宣称完成了该表示。源资产与可重新生成的运行缓存分开记录。

每个 SampleId 至少关联：WAV 相对路径、帧数/声道/采样率、基准音高/调音、播放方向、
循环模式与区间、来源及实际播放源。循环用 sample frame 为单位，明确采用半开区间
`[loopStart, loopEnd)`；到原 PCM 端点格式的换算由适配层处理，不能把两种定义混用。
音色定义保存 SampleId 引用和已恢复的分区/层规则，用户不填写 ROM 地址。

原厂导入器输出可编辑的 PCM 波形和公开元数据。导出必须标明已验证的解码初值、
速度/基准音高、精度映射和循环解释。运行中的相位/reference 等状态由算法推进，
资产保存其初始化与重建规则，不以预录全部运行轨迹代替状态算法。
原厂采样数量、边界和音色映射仍待取证，不能用按等长切片批量输出 WAV 代替恢复。

## 3. 原厂 bit 一致与用户编辑的共同边界

| 内容 | 播放路径 | 验收 |
|---|---|---|
| 未修改的原厂 bank | 从 metadata + PCM 建立经证明的等价设备输入/采样计算，复用原 PCM | stock 28、固定配置下与 GT 输出逐 bit 一致 |
| 修改/替换后的采样 | 从当前 metadata + PCM 建立播放数据，必要扩展采样源接缝 | 使用新素材，音高/循环/控制/快照正确；不要求等于原厂音频 |
| 仅有 WAV，缺少必需元数据 | 不能自动恢复原厂状态与映射 | 不自动继承严格兼容资格，需补齐或明确采用用户素材的定义 |

严格兼容资格必须同时绑定采样内容、播放定义与相关配置。全局原厂音频 gate 使用
完整未修改的 bank；修改包络或其他音色参数后，即使波形没变，也不能沿用该资格。

原编码可留在研究/对照产物中，但不规定为终态 bank 的必需文件。生产中若继续给
原 PCM 提供编码字节，这些字节应能够只从当前 metadata + PCM 重建；缓存可以删除
并重新生成，无需原 ROM 或另一份保存好的编码副本。也可以直接建立等价的解码输入，
但须证明原数值和状态转移相同。具体方式在 §7.4 的真实样本验证后确定。

不得将编辑后的 WAV 忽略掉，继续偷偷播放旧缓存。加载时核对规范化音频
内容（格式解释后的样本、帧数、声道和采样率）及相关播放定义，不能只比较路径或时间戳。
内容改变则失效派生数据，按当前素材及定义重建；若不能精确表示为原芯片编码，明确
采用已定义的扩展源或报告限制，不能默默有损重编码。重建失败不回退旧声音。
只改 RIFF 附加文本而未改音频不必失去资格；保留文件哈希用于来源追踪。
加载报告应能按 SampleId 列出最终文件、播放源和失去兼容资格的原因，便于定位。

更换共享 SampleId 的 WAV 会影响所有引用它的音色；只想替换一个音色时可复制采样
定义并改该音色引用。默认显式重新加载/重启生效，不要求首版提供实时热替换或 GUI。
重新加载以新 bank 身份建立状态，不在活跃 voice 下悄悄替换其底层存储。

## 4. PCM 接入：复用后续合成，增加采样源

当前 `pcm.cpp` 的 DPCM 与插值直接使用差分字节、缩放 nibble、reference 及地址状态。
`PCM_ReadROM()` 返回编码字节，不能把 WAV 的一个 16/24-bit 样本塞进它的 byte 接口。
依据见 [pcm.cpp](../../src/pcm.cpp) 的 address generator、dpcm、interpolation 和 filter 段。

优先从同一资产模型出发，按可逆性证据选择接入方式：

```text
metadata + 解码 PCM
       ↓
重建等价编码输入，或建立经证明的等价采样计算
       ↓
原 PCM 的滤波 / 音量包络 / 混音 / 效果
```

原厂路径保持原计算次序和数值规则；默认无 flag 分支保持原实现。用户素材不能用
原编码表示时，允许在 native 扩展采样源，按 voice 绑定来源。双源是可选实现手段，
不是资产模型的前提。所需改动限定在采样生成接缝，不能顺势重写滤波/效果或复制
一套逐渐与原实现分歧的 PCM 引擎。

这个接缝需要在 S3/S4 建立完整契约，不能仅增加一个 `float readSample()` 就算完成：

- 将 bank SampleId/播放定义绑定到 voice，与原生参数提交、key-on/off 和回收顺序协调。
- 自定义源持有自己的位置、方向、分数相位与循环状态；以宽 frame 索引表示 WAV 长度，
  不把用户文件硬塞回 20-bit ROM 偏移或原 3 MiB 布局。仍保持 M4.5 stock 28 容量。
- 结合 WAV 采样率、基准音高与原生 pitch/调制，恢复明确的推进量契约。导入时不得
  静默统一采样率、归一化幅度、裁剪长度或改变音高。
- 向滤波阶段交付的值要符合原 `test` 的数值表示，明确位宽、符号、缩放与量化。
  若采用新插值策略，要记录并验证；不能声称普通线性插值已与原差分插值 bit 等价。
- 保留原 PCM 更新节奏、active/key 状态、效果时钟以及单 IRQ 锁存协议。自定义源的
  循环/结束信号需有明确的固件兼容含义，不能擅自为所有完成的 voice 追加无限事件。
- 自定义播放状态归属 PCM 适配层，由 NativeSnapshot 连同 bank/SampleId 身份保存；
  不保存宿主指针。不匹配的 bank 恢复应明确失败，不能读取旧 ROM 补齐状态。

另一个可研究方案是将用户 WAV 编码回原 DPCM 格式，再走完整原 PCM。它能减少运行
分叉，但可能引入编码误差、循环约束和地址容量限制；不能默认对任意 WAV 无损。
本设计不将该编码器设为用户替换 WAV 的唯一入口。若采用它，需另行写出质量、容量和
循环契约，不能让这些旧限制悄悄成为透明资产的前提。

## 5. 输入与精度范围

首版至少支持标准单声道整数 PCM WAV 的 16/24-bit 素材，完整保留用户原文件。
24-bit PCM 可以承载已得到的 20-bit 值，但可逆解码不应预设只能保留这些已舍入值。
先确认解码过程中需保留的整数/小数精度、范围和溢出信息，再确定存储位宽与幅度映射。
保存格式无损不证明先前解码未丢信息；其他格式按明确能力表接受或报错。

采样率改变必须进入播放速率计算。文件长度或循环定义改变后，校验端点范围；缺失的
新素材参数不能猜。立体声如何占用 voice、float WAV 的转换与超范围幅度策略需要
单独定义，首版不得静默下混、裁剪或转码。任意长度仍受可用内存和声明的资源上限限制。

运行时缓存可以加速装载，须从当前 WAV/定义重新构建、用内容身份失效；用户不需要
编辑缓存。缓存不作为唯一资产来源，不要求原 ROM。公开 metadata + PCM 是权威资产，
原编码是取证参考，运行缓存是可重建产物，不能混为一谈。

## 6. 施工与验收

S0 的资产清单同时记录可试听采样与编码映射，先验证 §7.4 的表示完整性。S3 确定
采样源接缝；S4 先完成一个真实音色的“导入 → WAV 试听/编辑 → 重新加载 → MIDI 发声”
闭环，并保持原厂 bit gate。
S5 补齐运行范围内的采样映射和透明导出；S6 同时检查原厂兼容与用户替换能力。
不要求顺便制作新音色库或开发图形编辑器。

验收必须包含：

1. 未修改原厂 bank 的无原 ROM 运行、固定配置 GT bit 一致与默认分支回归，按 14 §8.1。
   清除运行缓存后也能仅从 metadata + PCM 重建，不读取研究产物中的原编码副本。
2. 普通播放器可打开导出的 WAV，采样与音色引用能从公开定义追踪；解码来源/条件可查。
3. 用本地生成的、波形明确不同的测试 WAV 替换一个采样，重新加载后证明新数据参与
   发声，而非只证明文件被打开。覆盖音高/时长/循环和控制行为，不能只用音频哈希改变。
4. 修改、删除或损坏 WAV 后，不能复用过期缓存；采样或必需元数据缺失明确失败。
5. 一个音色中原厂/自定义来源混用、共享采样引用、释放/抢音及保存恢复按契约运行。
6. 所有流程无需原 ROM、H8/SM 或 gen/hand 回退；用户素材不是“脱离原生路径的另一个播放器”。

原厂 bit gate 与编辑功能 gate 分开报告。替换素材后的音频差异是用户要求的结果；
仍须证明修改仅通过已定义的数据与播放规则生效，不能利用此范围掩盖原厂回归。

## 7. 可逆格式候选：区分样本无损与芯片播放等价

用户进一步询问能否用一种格式同时做到透明编辑、无损保存和可逆的 PCM bit 对齐。
**可以设计这样的开放资产容器，但普通线性 PCM 音频格式本身不保证芯片行为等价。**
本节是格式候选与取证要求，不表示已经确定全部恢复字段，也不新增运行实现。

### 7.1 三个不同的承诺

| 承诺 | 成立条件 |
|---|---|
| 线性采样值无损保存 | 保存足够位宽、明确幅度映射，读写不引入处理或量化损失 |
| 未修改资产导出再导入，恢复原厂播放 | 还需保存编码/缩放、初始与循环解释、地址关系等所有影响原 PCM 的信息，并验证恢复 |
| 任意编辑后的 WAV 无损编码回原芯片格式 | 不能由前两项推出；原编码的精度、缩放和布局约束可能无法精确表达新波形 |

任意新波形可以在自有格式中按其声明精度保存，但“保存无损”不表示原芯片编码器
一定能表示它。若新数据不在原格式可表示范围内，必须用明确的扩展表示/采样源，或
报告编码误差；不能以重编码成功冒充无损。编辑后恢复原波形及播放定义时，应重新
校验兼容身份；“撤销后恢复原样”与“改了声音仍等于原声音”不是同一个要求。

### 7.2 优先候选

编辑主格式仍优先 **WAV 24-bit 容器 + 公开恢复元数据**。WAVE_FORMAT_EXTENSIBLE 可
声明 20 个有效位，数据在 24-bit 容器中左对齐、低 4 位补零；该映射可逐值逆转，
不是降到 16 位或额外重采样。也可明确写成 24 个有效位的 PCM，并在元数据中保存
原精度与比例；两种写法的幅度映射不能混淆。
标准依据：[Microsoft WAVEFORMATEXTENSIBLE](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ksmedia/ns-ksmedia-waveformatextensible)。

恢复元数据可以使用 §2 的公开配套文件；如需要一个样本一个文件，可定义公开的
RIFF 自定义 chunk，内含同样的版本、采样身份、编码/缩放信息及必要恢复数据。
普通工具操作标准 `fmt/data` 音频部分，工程工具理解扩展部分；格式规范和查看/校验
工具必须开放。具体 FourCC 与 schema 待取证后确定，不在这里伪造已有行业标准。
[Microsoft RIFF 说明](https://learn.microsoft.com/en-us/windows/win32/multimedia/resource-interchange-file-format-services) 说明其分块容器结构。

不能假设所有通用编辑器保存时都会保留自定义块。因此配套元数据作为工程记录更易
与任意 WAV 编辑器配合；如果选择单文件，必须验证所支持编辑器的实际往返行为。
扩展块缺失、过期或与新音频不匹配时，不得继续认定严格兼容。恢复信息无论内嵌还是
外置，都会改变编辑后的有效性，不能靠选一个容器名自动解决。

FLAC 可以无损保存线性 PCM，并支持 APPLICATION 元数据；WavPack 的无损模式也可
保留所支持输入的音频及封装信息。它们可作为归档候选，但不会自动从 WAV 恢复原厂
DPCM 编码与插值语义，不必为了本目标新增音频库。
依据：[FLAC features](https://www.xiph.org/flac/features.html)、
[FLAC metadata](https://www.xiph.org/flac/documentation_format_overview.html)、
[WavPack 官方说明](https://www.wavpack.com/)。

### 7.3 当前算术规则的反例与证据边界

2026-09-13 对 `pcm.cpp` 的正数整数运算做了一个独立小核对，未提取 ROM 或运行合成器。
初始 reference=0、差分字节=1、插值系数 `interp_lut[0][0]=3385` 时：

| 缩放 nibble | 完整一步 DPCM 累积增量 | 该插值项的增量 |
|---|---|---|
| 0 | 1 | 1 |
| 15 | 1 | 0 |

可复算规则：`shift=(10-nibble)&15`；完整步先算 `v=(1*2048)>>shift`，增量为
`(v>>1)+(v&1)`；插值先算 `u=((3385*64*1)>>8)`，再算 `v=(u*2)>>shift` 并用
相同的增量规则。这里不发生饱和、乘法溢出或负数左移。

这说明只保留该完整步的线性结果可能丢掉影响分数相位输出的信息。它**不证明原厂
波形实际使用了上述组合**，也不是最终输出 int16 的 ROM 回归反例；需要从真实数据
确定缩放取值和可达状态。它足以否定“位宽足够就对所有输入自动 bit 等价”的推论。
该例中两种缩放值可以由 metadata 区分，因此它不能用来否定 metadata + PCM 的方案。

下一步的格式取证应选一个真实采样及循环边界，确认最小恢复信息，做未修改资产的
导出/导入、编码读取与多相位/多音高/循环状态对照，再做单点编辑与撤销。全程保持
已定义的数值和时间边界。优先验证 §7.4 的组合表示，按结果确定 §4 的接入方式；
在证明完成前保留取证信息，但不把研究用原编码副本规定为终态资产的必需部分。

### 7.4 优先证明 metadata + decode PCM 的完整性

明确区分两步：`原编码 → 解码波形` 是否保留了声音相关信息，以及 `解码波形 → 文件`
是否精确保留数值。后一步可通过足够精度的无损格式实现；前一步必须检查有无舍入、
饱和或截断。如果先丢信息再无损存盘，缺失的信息不会回来。

以 `E` 表示原编码采样与映射，`W` 表示解码 PCM，`M` 表示公开元数据。目标是：

```text
导入：E → (M, W)
运行：只用 (M, W) → 原 PCM 所需的等价数据/状态转移
```

不要求恢复与声音无关的 ROM 填充字节；必须恢复所有可观察波形读取、解码/插值和
循环状态的意义。元数据至少按真实取证包含播放/地址关系与初始化规则，缩放及其他
恢复字段是否需要、如何组织，应由逆变换证明；不能只写一个校验哈希代替缺失信息。
若发现解码舍弃了数值信息，优先提高波形表示精度；仍需补充的残差或恢复字段必须
说明意义、与采样的关系及编辑后的更新规则，不能把整个 E 借 metadata 原样封存。

第一项实验选择一个真实采样，含循环边界：仅从 M/W 重建设备读值或等价中间输入，
对照多音高/分数相位、方向、循环和复位状态；清空缓存复测，再做编辑、保存与撤销。
该实验通过后再冻结 bank schema 和最终采样源接缝，不能提前宣告所有原厂数据可逆，
