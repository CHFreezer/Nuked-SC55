# 透明 bank：提取元数据与波形，保存为 JSON + WAV

状态：**设计要求，尚未实现**。2026-09-13，按用户澄清简化资产提取与验收。
配套：[13 总目标](13_m45_native_reconstruction.md)、[14 架构](14_m45_native_architecture.md)、
[15 施工规程](15_m45_construction_guide.md)。

**任务就是把原素材的采样元数据和波形提取出来，保存为公开 metadata + 标准 WAV。**
用户可以直接试听、修改、替换采样，合成器加载这些文件发声。

## 1. 提取什么

- 波形：从 wave ROM 提取采样，按已有解码规则得到原始 PCM 波形；不烘焙滤波、包络或效果。
- 元数据：采样边界、循环、基准音高/调音，以及音色到采样的引用、分区等实际播放参数。
- 其他数据：原生控制算法需要的音色、参数和查找表，保存为有含义的数据。

元数据按实际来源提取；部分定义若位于固件数据表，就一并导出，不假定全部位于 wave ROM。
当前仍需确认具体表位置和采样边界，这是提取工具的工作。

## 2. 怎么存

使用普通目录和已有格式，例如：

```text
bank/
  bank.json                  bank 说明与索引
  samples.json               采样元数据，引用 WAV
  instruments.json           音色、分区与采样引用
  samples/
    piano_mid.wav
    piano_high.wav
  tables/                    原生算法需要的其他具名数据表
```

文件名仅为示意。元数据使用可读 JSON，波形使用标准 PCM WAV；按解码值所需精度保存，
优先使用 24-bit，确有需要再调整。保留原幅度、长度及音高关系，不顺便归一化或重采样。
多个音色可以引用同一采样。用户编辑 WAV 和对应元数据，无需填写 ROM 地址。

## 3. 怎么加载

同一个 `-mk2cpp` 原生控制后端支持两种音源选择，具体选择参数在接入时确定：

| 选择 | 加载内容 | 要求 |
|---|---|---|
| 原 wave ROM | 已提取的音色/参数表 + 用户指定的 wave ROM | 固定 stock 28 和同配置，与 GT 输出 bit 一致 |
| 透明 bank | metadata + WAV + 已提取的音色/参数表 | 不要求 bit 一致；未编辑的原厂导出素材保持无可闻差异 |

透明 bank 模式启动、播放、复位和保存恢复均无需原 ROM；选择 wave ROM 只是在加载声音
数据，两种选择都不运行 H8/子 MCU 固件。不加 `-mk2cpp` 仍保留原模拟器行为。

## 4. 复用原 PCM

保留现有 PCM 合成基础。wave ROM 继续走原读取、DPCM 解码与插值；WAV 增加所需的
采样读取、音高推进和循环处理，共用原滤波、音量包络、混音与效果。

当前 [pcm.cpp](../../src/pcm.cpp) 的 `PCM_ReadROM()` 返回编码字节，WAV 接入应放在
采样生成处，并保持原 PCM 所需的数值幅度与控制时序。播放位置等状态纳入现有原生
保存恢复工作，不另写整套声音引擎。

## 5. 编辑与替换

用户修改或替换 WAV 后，重新加载即使用新素材；需要时同时修改音高和循环定义。
共享采样的修改影响所有引用它的音色。文件缺失或元数据越界应报错，不能继续播放旧数据。
第一版以重新加载为准；若以后增加缓存，缓存必须随素材更新。

透明 bank 不要求重建原 ROM、重编码 DPCM 或证明编码可逆，也不附带原编码副本。
采用 JSON + WAV 即可，不为此设计自定义音频容器、恢复残差格式或新的归档体系。

## 6. 施工与验收

先提取一个真实音色，打通“导出 → WAV 试听 → bank 加载发声 → 修改后重新加载”，
再扩展到运行所需的完整采样与音色目录。S4 做通这条路径，S5 补齐资产。

检查保持简单：

- 导出的波形和元数据对应正确，WAV 能独立试听。
- 原厂透明 bank 播放的音高、循环和音色正确，与原路径对照试听无可闻差异。
- 替换 WAV 后实际使用新素材；透明 bank 模式无需原 ROM。
- 原 wave ROM 模式继续通过同配置 bit 对照；默认模拟器保持原行为，见 14 §8.1。

透明 bank 不增加可逆编码证明、统计盲听流程或另定一套音质评分门槛。
已有回归与用户试听即可作为检查手段；发现声音差异时直接定位提取或播放问题。
