# M4.5 原生算法重建（stock 28）

状态：**待实施**。2026-09-13 根据用户对最终代码形态的澄清，插入 M4 与 M5 之间。
本文定义目标、范围和验收，不表示原生引擎已经实现，也不重新启用复音扩展。
具体施工采用 [14 架构](14_m45_native_architecture.md) 与 [15 施工规程](15_m45_construction_guide.md)：
前者定义运行边界，后者给出阶段交付、算法契约和可读性门禁。

## 1. 目标的准确表述

**把 SC-55mk2 的固件行为和声音合成逻辑恢复为人能直接理解、修改和维护的原生 C++
程序：像从一开始就为现代 x86/amd64 编写的 MK2 软件合成器一样，用完整的算法函数、
有含义的数据结构和正常的控制流程，表达原版的 MIDI 处理、音色选择、音符管理、
声部分配、参数更新及声音生成。先保持原版 28 复音行为，再扩展到 256 个发声单元。**

“原生”在这里同时指运行方式和源码表达。C++ 编译成机器码只是已有条件；本阶段要让
正常播放路径直接执行合成器算法，读者无需在脑中模拟 H8/M37450 的寄存器、PC 和寻址。
目标是恢复 MK2 已有算法；漂亮的接口、通用合成器算法或近似听感都不能代替这项工作。

终态作为库编译进原 Nuked SC-55 程序。**保留并复用 nukeykt 的 PCM 芯片仿真、
LCD、RtMidi、SDL、资源加载与其他可用设施**，其中 PCM 仿真是获得原有声音的基础。
需要恢复的是固件控制逻辑及其状态，用原生 C++ 驱动已有设备与宿主设施。

### 1.1 入口与复用契约

| 项目 | M4.5 终态要求 |
|---|---|
| 不加 `-mk2cpp` | 原模拟器继续执行 H8/子 MCU 模拟与原设备调度，保留原有行为 |
| 加 `-mk2cpp` | 选择原生 C++ 控制分支，直接执行恢复后的固件算法 |
| 两个分支共用的基础 | 现有 PCM 芯片仿真、LCD 显示、RtMidi、SDL 窗口/事件/音频输出、ROM 资源设施 |
| 接入改动 | 为 MIDI/面板输入、LCD 状态、PCM 参数与时钟增加必要适配，保持设备行为 |

沿用同一程序与同一 flag，不另建应用或替换默认后端。**当前 flag 仍是 M1–M4 的
逐指令混合翻译入口**；把它提升为原生后端选择是待实施的 M4.5 工作。
两条分支复用设施的实现；启动时选定后端，不要求两套控制器同时驱动同一设备状态。

“脱离 MCU 指令执行”的限制作用于原生控制分支。PCM 芯片仿真中的寄存器、时钟、
状态机、查表和定点运算是需要保留的声音算法，不属于要清除的指令翻译框架。
M4.5 不新写替代 PCM 引擎；M5 再在既有 PCM 仿真基础上扩展原生分支容量，默认
模拟器分支仍保持原有行为。

## 2. 里程碑关系：保留 M4，补上算法重建

| 阶段 | 明确交付 | 当前状态 |
|---|---|---|
| M1–M3 | 主 H8 与子 MCU 的指令翻译、覆盖和差分基础设施 | 已完成 |
| M4 | stock 28 的 hand 逐指令整理、命名与模块划分、行为回归检查点 | 按本次限定的范围收口，代码基点 `97a0ae5` |
| **M4.5** | **完整的原生算法与状态重建；stock 28 行为等价；正常路径脱离 MCU 指令执行** | **待实施** |
| M5 | 在原生状态与声音内核上实现真 256 个同时活跃的发声单元，并验证性能 | 暂缓，依赖 M4.5 |

这是对原 M4 范围的显式拆分。此前要求的“人类可读语义 C++”尚未完成，现转入
M4.5；将 M4 记为检查点完成，不代表原语义目标已经验收。

**现有 M4 工作不回退。** 保留 hand 覆盖、命名、例程划分、ROM 映射、生成工具、
trace/hash/audio null 工具和已记录的回归结果。它们提供算法重建时的定位与比较基础。
复核依据见 [12 §1.2](12_polyphony_reassessment.md#12-m4-提交后复核命名整理与音频等价已取得进展语义目标未收口)。
当前 4239 个 PC 入口与零 `case 0x` 是检查点事实，不是原生算法完成的指标。

逐个替换经过验证的模块，保留可选择的参考后端。过渡期可以使用 PC/内存适配和混合
执行；M4.5 最终验收时，原生后端的启动、复位和正常播放不能依赖这些指令路径。

## 3. 什么代码才算完成

可读性的验收单位是**完整业务操作及其调用链**，例如初始化 voice 池、按原优先级
选择可用或被抢占的 voice、处理 Note Off 与 sustain、推进一轮包络、提交 voice 参数。

- 函数边界对应这些操作；主体能看到真实的计算、条件、遍历和状态转换。
- `Part`、`Note`、`Voice`、空闲池、音色参数、包络状态等具有经证据确认的字段与关系。
  读者能够追踪一个 MIDI 音符如何创建、更新、释放其发声单元。
- 控制流使用 C++ 的调用、分支、循环或有业务含义的状态机；不靠原 ROM PC 推进。
- 原始地址、字段偏移、反汇编对应与差分诊断留在数据解码、迁移适配或证据文档中。
  原生业务层通过明确的状态与接口取得数据。

**仅把指令改成 `step_*()`、给寄存器换名字、把 PC 分派藏进 helper，或将很多单行
指令函数拼成调用列表，均不算完成。** 文件数量、hex 数量、case 数量、函数长度也不能
单独决定完成度。短小且有明确用途的 helper、位掩码、硬件格式常量和查表算法可以保留。

数据类型按算法选择。`uint8_t`、`uint16_t`、整数、定点和显式截断都可以是正常 C++；
影响声音或外部行为的溢出、符号扩展、舍入和饱和必须准确表达。机械扩大所有类型或
统一改用 float 不属于本阶段目标。用户的浮点滤波路径作为单独配置保留并分别验证。

尚未理解的字段和分支要记录证据、未知含义与影响范围；不能猜一个业务名就宣告恢复。
影响本阶段完整行为的未知项应留在未完成清单中。

## 4. 重建范围与保真边界

M4.5 的终点是完整的 MK2 原生运行路径。voice 子系统可以先做，但只完成它不足以收口。

| 范围 | 需要恢复和表达的内容 |
|---|---|
| MIDI 与控制 | 消息解析、GS/SysEx、控制器、part 参数、程序与音色选择、复位行为 |
| 音符与分配 | Note On/Off、重复同音配对、sustain/release、多 voice 音色、抢音与回收规则 |
| 发声参数 | 音高、包络、LFO、插值/查表及原固件的参数更新与提交算法 |
| 声音生成 | 继续由现有 PCM 芯片仿真完成波形寻址、插值、滤波、混音和效果；明确原生控制接口及更新次序 |
| 时间与状态 | MIDI 到发声的可观察时序、控制更新频率、PCM latch/commit、初始化、复位、状态保存恢复 |
| 子 MCU 与面板 | 主/子 MCU 协作中影响 MIDI、控制和显示的逻辑，以及已有面板操作的可观察行为 |

波形、音色和参数表仍可从 ROM 读取，它们是数据资产。读取和解析 ROM 数据不等于运行
ROM 指令。需要为代码/数据边界建立证据，不能为了摆脱 ROM 执行而擅自替换原表或算法。

`src/pcm.cpp` 作为 PCM 仿真实现继续使用，保留内部状态、数值算法和声音行为。
审计与适配重点是如何从原生逻辑写入参数、读取完成状态、推进 PCM 时间，并与
现有音频输出连接。原生时间可以换算为既有 PCM 接口需要的周期单位，M4.5 不必
改变芯片内部寄存器表示或固定槽布局。容量、效果槽布局及扩展混音策略的改动属于 M5。

LCD 渲染、RtMidi 端口接收、SDL 窗口与音频设备管理继续沿用。恢复固件对面板/MIDI
和显示状态的处理，不等于重写这些基础设施。共享设施的必要适配必须验证默认分支。

原生调度以音频时间和已恢复的逻辑事件组织，不要求永久保留“一条 H8 指令一次宿主
循环”。凡指令时序会影响事件先后、参数提交或输出，就必须先恢复对应约束，再替换
执行机制。不能把整个例程当作瞬间完成，最后一次性补周期便认定等价。

现有 `MK2CPP_HandBoundary()` 尚无实际调用者，当前 L0 回归没有验证 L1 长例程运行。
如过渡实现使用 L1，必须另行验证例程内部的中断、MIDI、PCM、定时器和子 MCU 服务；
L1 是可选的迁移手段，不是终态必须保留的指令框架。

保真分两条记录：

1. **重建等价**：固定 ROM、输入时序和 PCM/滤波配置，与选定 GT 参考后端对照。
2. **实机还原**：MK2 PCM 滤波等已有模型差异继续单独研究；通过 GT null 不能证明
   已补齐实机差异。来源与用户浮点版本的边界见 [12 §1.1](12_polyphony_reassessment.md#11-pcm-芯片资料mk2-滤波近似与浮点版本)。

## 5. 实施顺序

1. **建立完整算法样板**：选择 voice 池初始化及分配/释放这一有既有研究的例程族，
   列清输入、状态字段、所有读写者、调用关系与时序约束，写出可独立阅读的算法实现。
   首先验证 stock 28 的链表、计数、分配次序和边界事件，形成后续模块的标准。
   首片细化为空闲队列完整操作（15 §4），不提前宣告整个 pool-init/allocator 已完成。
   同时开始 PCM/任务时序取证，不能等算法全部写完才调查设备接入。
2. **贯通音符到发声路径**：连接 MIDI 音符、part/音色、voice、包络/音高及 PCM 参数
   提交。恢复完整的生产者与消费者，避免新状态仍被旧固件地址布局限制。
3. **补齐运行依赖与原生调度**：恢复剩余控制、GS/SysEx、主/子 MCU 协作、面板、
   初始化与复位等行为；用明确的逻辑事件和声音内核接口完成运行闭包。
4. **stock 28 收口**：完成下列三项门禁，再进入 M5。每个切片有局部差分结果，不能
   用局部通过代替整条原生路径完成。

建议新增 `src/native/` 承载算法核心，`src/hand/` 保留 M4 参考实现；这是拟定的目录
职责，本次文档变更没有创建运行模块。实际模块可以按研究结果调整，验收边界不变。
原生状态由自身持有，必要的旧内存视图留在适配层；新增状态必须纳入复位和保存恢复，
不能继续沿用“M4 hand 无私有状态，所以不需要处理快照”的结论。

## 6. 三项收口门禁

| 门禁 | 验收要求 | 不足以替代它的结果 |
|---|---|---|
| 算法与可读性 | 完整算法、字段含义、调用关系及状态所有权可审阅，能从输入追踪到输出；关键未知项已闭合 | 函数改名、零 case、PC 覆盖率、只添加结构体外壳 |
| stock 28 行为与原路径保留 | 原生分支固定配置下音频 null、MIDI/控制/面板、关键时间、启动/复位/保存恢复对照通过；不加 flag 的原模拟器回归通过 | 只测一个短音频窗口，或只证明原 L0 仍通过 |
| 原生运行闭包 | 原生模式启动和正常运行不执行主/子 MCU 指令，不按 PC 分派 gen/hand，也无解释器兜底；调用依赖审计与运行诊断共同证明 | 解释器 fallback 为零，但仍在逐 PC 执行生成的 C++ |

音频默认要求相同配置下逐样本一致；如出现差异，先定位，不得自行放宽容差来掩盖
尚未恢复的时序或数值行为。实机滤波改进与容量增强另立基线。
内部表示可以变化：H8 寄存器、PC、原 SRAM 的逐字节相同不再是原生后端的强制要求；
应比较映射后的逻辑状态、事件、PCM 提交和输出。对照适配不能让原生算法重新依赖旧布局。

测试遵循 [README](../README.md) 的默认回归范围和预算。按变更补充有针对性的合成输入，
覆盖 sustain/release、抢音、复位等对应分支；不因新增里程碑自动跑全量曲库或压力矩阵。
正式听感验收遵循已有用户在场规则，记录测试版本、配置、窗口及结果。

## 7. M5 接续与旧文档适用范围

M4.5 完成后，M5 才扩展由原生逻辑持有的 voice 池、标识与计数、mask、PCM 发声状态
及其全部读写者，PCM 扩展以原有仿真实现为基础，容量增强仅作用于原生分支。
目标为 **256 个同时活跃的底层发声单元**；多 voice 音色不保证
256 个 MIDI 音符同时发声。255 是旧实验的哨兵妥协，不能作为最终验收。

扩展应验证越过 28、32、128 到达 256 的边界，以及回收、效果槽隔离、混音和实时性能。
原版 28 复音兼容配置继续保留；增强配置的容量差异与必要混音策略单独说明。
旧 `0xE800`、page6/7 和固件补丁设计是历史研究，不再规定原生实现必须走该路径。
