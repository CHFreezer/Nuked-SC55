# SC-55 mk1 PCM 芯片全管线 → SCCore.dll 逐段对照调研

**对照对象（芯片参考）**：Nuked-SC55 `src/pcm.cpp` —— Roland PCM ASIC（mk1 = R15239148，John McMaster 唯一公开 die）的逆向实现，`PCM_Update()` 是整条管线。
**被调研对象（软件）**：`C:\Program Files\Roland VS\SOUND Canvas VA\SCCore.dll`（27 MB，x64 PE，ImageBase `0x180000000`）。它是 Roland 官方 **SC-GS / SC-8820 / XP-GS「Tone Generator」**（`.rdata` 产品横幅），自包含 C++ x64，播 Roland **SSW SC-8820 音色库**（`SCVSC.tnf` + `.drk/.drf`），DSP 为 **float32 SSE**。
**日期 / 工具**：2026-09-05 ｜ `llvm-objdump` / `llvm-readobj` / `llvm-strings`（`C:\Program Files\LLVM\bin`）；全量反汇编 `re/sc.asm`（131,130 行）。
**姊妹篇**：`scgs_operational_boundary.md`（数值边界）、`scgs_filter.md`（滤波器专题）。本篇回答的是**「整条芯片管线在 DLL 里是不是都有对应、算法是否相似/更先进、芯片硬件如何在软件里实现」**。

---

## 0. 结论速览（先答四个问题）

**Q：mk1 PCM 芯片的整条管线，是不是在 DLL 里都有对应？**
→ **每一段都有对应**，但对应关系是「**拓扑等价、实现重做**」：芯片的**逐声部链**（相位→样本读取→插值→滤波→包络→LFO→增益→混音→混响/合唱）在 DLL 里**逐段可找到**；芯片**特有的数据/硬件**（4-bit DPCM 波形 ROM、16-bit LFSR 噪声、E-RAM 混响网络）则被**换成** Roland SC-8820 音色库（线性 PCM 采样、录音噪声采样、SC-8820 FX 程序）。

**Q：算法是否相似 / 更先进？**
→ **拓扑高度相似**（这验证了 pcm.cpp 的结构是对的），**数值实现全面更「高级」**（float32 vs 20-bit 定点、4-tap vs 3-tap 插值、批处理 vs 逐周期、递归 LFO 整形 vs 1-bit 相位）。**「更先进」要打折**：它不是「把芯片算法算得更准」，而是**用现代 float 架构重写了同一条链**，并把芯片里靠硬件压缩/合成的部分（DPCM、LFSR）**外包给数据**。

**Q：PCM 芯片硬件怎么在软件上实现？**
→ **逐段映射见 §1/§2**。核心：芯片的**硬件功能单元**（相位累加器、DPCM 解码器、插值 LUT、谐振滤波器、包络发生器、噪声 LFSR、混响 E-RAM）在 DLL 里变成**C++ 里的浮点循环 + 静态查找表 + 运行时 BSS 状态**。硬件的「每周期一拍」变成「每帧批处理 N 拍」（batch renderer）。

**Q：对 mk2 爆音意味着什么？**
→ 见 `scgs_operational_boundary.md` §6。本篇补充：芯片的**饱和是 20-bit 定点的必需品**，而 VSTi **因为 float 裕量大而天然不需要饱和**——两者「都不饱和」的原因不同；芯片管线里**每一段都在 VSTi 里有 float 版**，所以「哪一段在 mk2 上跑飞」可以逐段用 VSTi 的 float 版当基准去比。

## 2. 逐段详解

### 2.1 时钟 / 相位

- **芯片**：14-bit 相位 + 7-bit 插值分数，MCU 每周期推进一次；`tv_counter`（14-bit）另作包络时基。
- **DLL**（`0x18003f9d0` 读取器内）：
  ```
  phase    = (u16) 0x46(%perVoice)          # 16-bit 相位
  lutidx   = (phase >> 9) * 2               # 上 7 bit → 128 项 LUT 分数
  newPhase = phase + rate                   # rate = perVoiceTable[0]
  0x46     = (u16) newPhase                 # 回写低 16 bit
  carry    = newPhase >> 16                 # 溢出 → 推进样本索引 0x28
  ```
- **对照**：芯片「粗相位 + 7-bit 分数」的切分被**原样保留**（DLL 上 7 bit 正好选 128 项 LUT，和芯片 7-bit 分数同义），只是相位总线宽到 16 bit、速率是 float（亚样本精度），不再受 MCU 整周期约束。

### 2.2 样本读取 + DPCM 解码（★最大差异）

- **芯片**：波形以 **4-bit DPCM** 存 ROM；每样本附带一个「步长 nibble」，`PCM_Update` 里**逐样本解码**（`~1293-1333`）——这是芯片硬件解码器。
- **DLL**：读取器是 **6 模式分发器** `0x18003f720`（按 `0x48(%rcx)` 的 bit5 + bit1-2 分发到 `0x18003f9d0`/`0x18003fb80`/`0x18003fdd0`/`0x18003f775`/`0x1800403c0`/`0x180040610`）。**mode0（`0x18003f9d0`）直接读 float32 线性样本**：
  ```
  xmm5 = float @ sampleData                 # 当前样本，已是线性 PCM
  环形缓冲 4 样本 @ 0x14(%r11)             # samp0..samp3
  加载器 0x18003f870：每 16 拍从 *(0x20(%rcx)) 补 4 个 int32 → 环形缓冲，
                          检查循环标志 bit 0x10，边界做 shufps[1,2,3,0] 轮换
  ```
- **结论**：DLL **没有 DPCM 解码器**。样本是**预解码的线性 PCM**（Roland SC-8820 音色库本来就是全精度采样）。芯片「DPCM 解码」这一段在 DLL 里**整段缺席**，被「读全精度数据」取代——**芯片省存储、DLL 省算力**，是同一环节的两种设计取舍。
- **对 mk2 含义**：DPCM 解码误差（步长量化）在 mk1/mk2 都一样来自 ROM 数据；DLL 用全精度采样，**这一段的 mk2 差异为零**——可排除。

### 2.3 插值器

- **芯片**：`interp_lut[128]`，**3 抽头**线性插值，7-bit 分数。
- **DLL**：**静态 128 项 × 4 抽头**带限插值 LUT，固化在 `.data`（`0x181a0f210`，出厂即有，非运行时生成）：
  ```
  w   = LUT[lutidx]        # movups 一次取 4 个系数
  out = w0*s0 + w1*s1 + w2*s2 + w3*s3   # 4 样本环形缓冲，haddps×2 归约
  out *= 当前样本系数(xmm4)
  ```
- **对照**：**4 抽头 > 芯片 3 抽头**，且是预计算带限曲线（抑制镜像/混叠）。这是「略更先进」的一小步：拓扑同类（LUT 分数插值），抽头数多一个。

### 2.4 谐振低通滤波器（已完整解码，见 `scgs_filter.md`）

- **芯片**：2 积分器 State-II，**每次加法 `addclip20` 20-bit 饱和**（±524288，是音色的一部分）。
- **DLL**：同一 State-II 拓扑，**纯 float、每样本不饱和**；标量（`0x18008ce70`→4 变体，仅输出抽头/系数取法不同）+ **SIMD 一次 4 声部**（`0x18008d9a0`）。
  ```
  state2 = state1*B + state2;   out = state2;
  err    = in - (state2 + state1*A);   state1 += err*B;
  ```
- **对照**：**拓扑一致（验证 pcm.cpp 结构）**，**精度更高**（float vs 20-bit），**边界行为相反**（芯片饱和、DLL 不饱和）。系数拆分也不同（芯片 s2 收 3 项 + s1 收 2 项；DLL 2 系数 + 前馈零点）。**这是 mk2 爆音的主嫌疑段**——详见 `scgs_operational_boundary.md` §6。

### 2.5 包络 / ADSR

- **芯片**：`calc_tv()`（速率表 + 指数衰减），每声部调用 ×3 得 volmul1/volmul2（`~319`，`~1432-1437`）。
- **DLL**（控制面 `0x18008c2c0`）：**一阶整数斜坡**——每 tick 把 32 个控制量（`r11`=0..32）各自向目标推进**固定比例**：
  ```
  step = (target - current) * 3 / 256      # lea *3 ; shl 8 ; sar 16（含取整）
  current += step;                          # 每 tick 逼近，指数式收敛
  out  = float(current) * scale            # cvtdq2ps + mulss，写立体声 [0]/[4]
  ```
  随后还有 `0x181a19770`/`0x181a190f0` 一带的 **33 元点积 × 8 组**（FX 抽头权重）。
- **对照**：**同为「把电平随时间推向目标」，实现不同**：芯片走**速率表 + 指数**（DLS/SC-88 标准 ADSR 的离散表），DLL 走**一阶线性逼近**（每步固定比例）。听感上都是指数包络，但**逐采样曲线不逐点相同**——A/B 时包络尾音可能有一点点差异。
- **对 mk2 含义**：包络是**逐点可复现**的一段（不涉及 20-bit 边界），若 dry A/B 在包络上完全吻合，就能把 mk2 差异**排除出包络、集中到滤波器**。

### 2.6 LFO

- **芯片**：1-bit 相位 LFO，MCU 定时驱动（锯齿/方波类）。
- **DLL**（`0x18008aca0`）：**float 批处理 LFO 生成器**：
  - 相位 `0x14(%rdx)` 在 **[0,1)**，`rate` 是 **float**（亚样本精度）；到 1.0 减 1 回绕。
  - **32 子步内环**（`0x10` 计数器到 0x20）：每步推进一个 2 极递归整形（`0x30/0x34/0x38/0x3c` 状态），读速率表 `0x181a18f70`，双输出指针 `r10/r11`。
  - **批处理**：一次生成多拍 LFO 值（与批渲染器一致）。
- **对照**：**更先进**——递归整形（比 1-bit 相位平滑）、float 速率、32:1 子步抗锯齿。拓扑上「相位累加 + 整形」对应，但精度/平滑度高一档。

### 2.7 噪声

- **芯片**：**16-bit LFSR**（`~583-607`），硬件实时合成白噪声，喂噪声音色。
- **DLL**：`.text` **无 `xorl %reg,%reg` 自反馈**（LFSR 特征缺失）；字符串里的 "noise" 全是 **SC-8820 音色名**（"Organ Noise"、"Noise Piano"、"Gt.FretNoiseL"、"Breath Noise"、"Noise&SawHitP"…）→ 噪声是**录音采样**，走 §2.2 的样本读取路径。
- **对照**：**整段换数据**——芯片 LFSR 硬件合成，DLL 用录音。噪声「颜色」（LFSR 频谱 vs 录音频谱）**不同**。
- **对 mk2 含义**：噪声色度差异在 mk1/mk2 间**本就不逐点可比**（不同硬件 LFSR 多项式都未必相同），且 DLL 用录音 → 噪声**不是 mk2 爆音的来源**，可排除。

### 2.8 增益 / 声像 / 主混音 / DAC

- **芯片**：逐声部 gain/pan，ch30 求和，`<<12` 后走 20-bit DAC。
- **DLL**：float 求和，两级限幅（见 `scgs_operational_boundary.md` §3）：
  - **±1.0 归一化**（`0x180006bdc`，`comiss`+分支）
  - **±16.0 int32 满量程**（`0x180005ce4`，越界钳 `±0x7FFFFFFF/0x80000000`，再 `cvttss2si` **截断**）
- **对照**：同功能，**精度高一档**（float 内部 + int32 输出，24-bit 余量）。芯片 `<<12` 定点缩放 ≈ DLL 的常数 `mulss`。

### 2.9 混响 / 合唱

- **芯片**：**E-RAM 延迟线网络**（M37450M2），ch28/29/30，4-bit 存储，MCU 编程抽头/反馈。
- **DLL**：**SC-8820 标准 FX 程序**（`.rdata` 名表实测）：
  ```
  Chorus 1    Chorus 2    Chorus 3    Chorus 4    FB. Chorus
  Flanger     Short Delay Short FB Dly
  （另有）St. Flanger / Step Flanger / Hexa Chorus / St. Chorus /
          3D Chorus / Reverb / Gate Reverb
  ```
  float 延迟线网络，抽头权重在 §2.5 点积路径更新。
- **对照**：**同为「延迟 + 反馈网络」，但网络不同**：芯片是 M37450M2（4-bit E-RAM、固定拓扑），DLL 是 SC-8820/DLS 标准（float、可选程序）。**「整体气质不对」的另一主来源**（`scgs_operational_boundary.md` §7 单列过）。
- **对 mk2 含义**：FX 在 mk1/mk2 间**同源**（都是芯片 M37450M2），所以 FX **不是 mk2 特有差异**；但它和 VSTi 不同 → 是「芯片 vs VSTi」音色差的主要来源之一。

## 3. 专题：芯片硬件如何在软件里实现

| 芯片硬件单元 | 软件实现（SCCore.dll） |
|---|---|
| **时钟 / 相位寄存器** | 每声部结构里的 16-bit 相位字段 `0x46` + float 速率；「每周期一拍」→「每帧批处理 N 拍」 |
| **DPCM 解码器** | **取消**——直接读全精度 PCM（数据侧预解码） |
| **插值 LUT（ROM）** | 静态 128×4 带限 LUT `0x181a0f210`（`.data` 出厂固化） |
| **谐振滤波器（ALU）** | State-II 浮点循环，标量 + SIMD(4 声部) 双实现；**每加一饱和** → **无饱和** |
| **包络发生器（速率表）** | 一阶整数斜坡（每 tick 固定比例逼近目标）+ 立体声 float 输出 |
| **LFO（相位寄存器）** | [0,1) 相位累加器 + 2 极递归整形 + 速率表，32:1 子步，批处理 |
| **噪声 LFSR** | **取消**——录音噪声采样 |
| **混音 DAC** | float 求和 + 两级标量限幅（±1.0 / ±16.0）+ `cvttss2si` 截断 |
| **混响 E-RAM（M37450M2）** | SC-8820 标准 FX 程序（float 延迟线，抽头权重运行时更新） |
| **MCU（寄存器编程）** | 参数更新路径写 BSS 里的每声部系数表（`0x181a1c…`/`0x181a1d…` 等） |

**两条「外包给数据」的替换**（DPCM、LFSR）是关键：芯片靠**硬件单元**做的两件事，DLL 靠**数据**做了。其余单元是「硬件功能 → 浮点循环 + 静态表 + 运行时状态」的直译，拓扑保留、精度抬高、去掉定点饱和。

## 4. 综合判断

1. **管线完整性**：芯片 9 段管线在 DLL 里**逐段都有对应**；2（DPCM）与 7（LFSR）是「整段缺席、换数据」，其余 7 段是「拓扑保留、float 重实现」。
2. **相似度**：**逐声部链拓扑高度一致**（相位→读→插值→滤波→包络→LFO→增益→混音），这**独立验证了 pcm.cpp 的管线结构**。数值实现全面 float 化，**边界行为相反**（芯片定点必饱和，DLL float 不饱和）。
3. **「更先进」的准确说法**：不是「把芯片算法算得更准」，而是**现代 float 架构重写 + 芯片硬件压缩/合成（DPCM、LFSR）外包给数据**。精度更高、抗锯齿更好（4-tap、LFO 子步），但**不是逐位复刻**。
4. **定位**：**软参考**——可用它确认管线/拓扑、做 dry-voice A/B、看趋势；**不能逐采样 A/B mk2**（float32 vs 20-bit 定点）。
